Hackathon Documentation

============================================================
1) Executive Summary
============================================================
NykaaSight is a full-stack web application that allows non-technical users to create
interactive business dashboards using plain English.

Instead of writing SQL or manually configuring BI tools, a user can ask:
"Show me monthly revenue trend and best channels by ROI."

NykaaSight will:
1. Parse and understand the request using an LLM.
2. Retrieve relevant dataset context and prior chart memory.
3. Generate chart configurations in strict JSON format.
4. Process data and render interactive charts in real time.
5. Save chat history and dashboard snapshots for reuse.

This directly solves reporting bottlenecks for business teams and executives.


============================================================
2) Problem Context (Simple Explanation)
============================================================
Most business teams have lots of data but limited technical access.
If every question needs a data analyst, reporting becomes slow.

NykaaSight reduces this dependency by giving executives a conversational interface:
Ask in English -> Get dashboard instantly.

============================================================
Goal:
Build an intelligent system that converts natural language requests into complete,

NykaaSight solution:

Storage (Supabase PostgreSQL):
- datasets
- chat_sessions
- chat_messages

- dashboard_snapshots


============================================================
6) Architecture (End-to-End Flow)
============================================================
Flow A: CSV Upload
1. User uploads CSV.
2. Server parses rows and infers schema.
3. Dataset metadata saved in Supabase.
4. Full rows cached in memory for fast chart processing.
5. Background vector indexing stores semantic chunks.

Flow B: Conversational Dashboard Generation
1. User asks a question.
2. Backend retrieves relevant vector context from embeddings.
3. LLM receives schema + sample rows + retrieved context + history.
4. LLM returns strict JSON (reply + chart configs + follow-ups).
5. Backend processes chart configs into chart-ready data.
6. Frontend renders charts using Recharts.
7. Chat and chart memory are persisted.

Flow C: Follow-up and Snapshot
1. User asks modification prompt ("only top 5", "remove pie chart").
2. Existing chart state is passed to LLM.
3. Updated chart configs are merged by chart id.
4. Snapshot can be saved and restored later.

9) Judging Rubric Mapping
============================================================
9.1 Accuracy (40)
Data Retrieval:
- Chart data is computed from parsed dataset rows with filter, group, aggregate, sort, limit.
- Supports aggregation: sum, avg, count, max, min.

Contextual Chart Selection:
- Prompt instructions enforce chart type rules (time series -> line/area, part-of-whole -> pie, etc.).
- Backend now normalizes chart type variants for resilience.

Error Handling:
- Handles malformed AI JSON with parsing fallback and user-friendly error message.
- Handles missing dataset/cache and invalid upload cases.
- Degrades gracefully when vector memory retrieval fails.

9.2 Aesthetics and UX (30)
Design:
- Professional dashboard style with strong visual hierarchy.

Interactivity:
- Tooltips, legends, responsive charts, chart type switching, full-screen chart view.

User Flow:
- Guided upload states (uploading, indexing, done).
- Chat loading state and suggestion chips.
- Snapshot save/load and session history.

9.3 Approach and Innovation (30)
Architecture:
- Structured pipeline from text -> LLM -> processed chart data -> UI.

Prompt Engineering:
- Strict JSON-only response contract.
- Context injection with schema, sample rows, retrieved vector memory, and current dashboard state.

Hallucination Handling:
- System forces data-grounded outputs.
- When parsing fails or response is unclear, app returns safe user-facing message.

11) 10-Minute Demo Plan (3 Progressive Queries)
============================================================

- Load "Nykaa Demo" dataset or upload custom CSV.

Query 1 (basic):
"Show monthly revenue trend and total conversions by month."

"Compare ROI by Channel_Used and show top campaign types by conversions."
Expected: ranking bars + channel comparison.

Query 3 (advanced follow-up):
"Now keep only top 5 channels, remove weak performers, and show segment-wise revenue share."
Expected: updated charts + pie/part-of-whole visualization + refined insights.

Wrap-up:
- Save snapshot.
- Open history.
- Export/print dashboard.
